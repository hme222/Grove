# Deploy the Grove API on Render

The API (`grove-backend`) needs a host that keeps a Python server running. The app frontend and the landing page stay on Vercel.

## Set it up

1. In Render, choose **New → Blueprint** and connect the `hme222/Grove` repo. Render reads `render.yaml` in the repo root.
2. Fill in the values it asks for:
   - `MONGO_URL`: the Atlas `mongodb+srv://…` string for a dedicated backend user (readWrite on `grove_db`). URL-encode special characters in the password. No quotes or spaces.
   - `CORS_ORIGINS`: the address of the deployed app, for example `https://app.floragrove.app`. Use commas for more than one. Don't leave it as `*`, because the API sends credentials.
   - `ANTHROPIC_API_KEY` is optional and not in the Blueprint. Without it the API runs, but the AI features (plant identification, room scan, photo checks, watering suggestions, biographies) fail when used. To turn them on, add it in the service's Environment tab.
3. `JWT_SECRET` and `JWT_REFRESH_SECRET` are generated by Render. Don't remove them. The code has no built-in default any more: with `APP_ENV=production` it refuses to start without them, and without that flag it uses a random secret that changes on every restart (everyone is signed out). Set `APP_ENV=production` on Render.
4. Never set `ENABLE_TEST_LOGIN` on a deployed server. It turns on the credential-free `/api/auth/test-login` route for local testing only.
5. The seeded test accounts need `GROVE_TEST_PASSWORD` (12+ characters) in `grove-backend/.env`; it is not stored in the repo. After changing it, run `python3 scripts/rotate_test_accounts.py` (dry run first) so the database matches.
4. When the deploy is live, `https://<service>.onrender.com/healthz` should return `{"ok": true}`.

## Connect the frontend

In the Vercel project for `grove-frontend`, set `REACT_APP_BACKEND_URL` to the API's public address (no trailing slash), then redeploy the frontend. Create-React-App reads it at build time, so a change needs a new build.

## Atlas

Network Access must allow Render. It has no fixed address on the free plan, so `0.0.0.0/0` is needed, which the landing page already uses.

## Free plan limits

Free web services sleep after 15 minutes without traffic, and the first request after that takes about a minute. Move the service to a paid instance before launching to real users.

## Not tested yet

`requirements.txt` is pinned for a newer Python than the 3.9 used on the development machine. The first Render build is the first time it is installed on Python 3.12, so check the build log if it fails.
